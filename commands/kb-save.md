---
description: 직전 분석을 지식베이스(qa-log / deep)에 저장
---

직전 대화의 분석과 답변을 `.agent-context/`에 영구 저장한다. 두 곳에 동시 저장 가능하다.

1. **항상** — `qa-log/` (이번 건의 기록)
2. **영역 흐름 분석이 발생했으면** — `deep/` (해당 영역의 동작 지식)

## 절차

### 1. 저장 내용 정리
- 질문 원문
- 핵심 답변 (원인 / 위치 / 영향도 / 검증 방법)
- 관련 파일과 라인 (`file:line`)
- 검증 절차 (있었으면)
- 관련 티켓 키 (있었으면)

### 2. 자동 결정 (묻지 않는다)
`부분확인`과 `가설` 저장은 **저위험이므로 확인 없이 자동 실행**한다.
저장이 대화를 블로킹하면 지식이 안 쌓인다.

- slug 자동 결정
- 태그 자동 추출
- deep 저장 여부 자동 판단
  - 영역 동작·흐름 분석이 발생했으면 → `deep/{영역}-{흐름}.md`
  - **재발 가능한 증상을 새로 풀었으면 → `deep/voc-{증상}.md` 진단 레시피**
  - 단건 사실 확인뿐이면 qa-log만

**유일한 사전 확인 게이트 = `상태: 확정` 승격.** 그 외에는 저장 후 결과만 보고한다.

### 3. qa-log 저장
파일: `.agent-context/qa-log/{YYYY-MM-DD}-{slug}.md`

```markdown
---
date: YYYY-MM-DD
tags: [영역, 키워드]
related: [[deep 파일명]]
---
상태: 부분확인

## 문의
{질문 원문}

## 답변
{핵심 답변}

## 근거
{파일:라인, 확인한 데이터}

## 검증
{재실행 가능한 절차} / 기대: {값}
```

### 4. deep 저장 (영역 분석이 발생했을 때)
파일: `.agent-context/deep/{영역}-{흐름}.md`

**동작·흐름 수준으로 쓴다.** 커밋 레벨 디테일(라인 번호, 미커밋 여부)은 최소화한다.
코드가 바뀌면 썩는 내용은 재사용되지 않는다.

### 4-b. 진단 레시피 (재발성 증상)
파일: `.agent-context/deep/voc-{증상}.md`

```markdown
상태: {가설|부분확인|확정}
검증: {재실행 가능한 절차} / 기대: {값}

# {증상} 진단 레시피

## 증상
## 확인 순서
1. {어떤 데이터를 어떤 순서로 볼 것인가}
## 책임 분기
- {조건} → 자사 (조치 대상)
- {조건} → 외부 (이관)
## 함정
{빠지기 쉬운 오해와 그 이유}
```

### 5. 확정 졸업 가드
`상태: 확정`으로 올리려면 **재실행 가능한 검증 줄**이 있어야 한다.
못 만들면 `부분확인`에 둔다. 확정 승격은 **사용자 확인 후** 진행한다.
